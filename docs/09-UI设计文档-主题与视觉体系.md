## 1. 现状评估

### 1.1 评估方法

对 `app/lib` 全量源码进行静态走查（177 个 Dart 文件，15 个 feature 模块），从布局、配色、字体排版、视觉风格一致性四个维度评估，问题按 P0（阻断）/P1（显著）/P2（优化）分级。

### 1.2 界面布局

| 维度 | 现状 | 评级 | 说明 |
| --- | --- | --- | --- |
| 页面框架 | 单 AppBar + IndexedStack + NavigationBar + FAB（`lib/app.dart:117`），五 Tab 结构清晰 | 良 | 历史上"嵌套 Scaffold 双 AppBar"问题已在 v0.2.1 审查后修复 |
| 二级页导航 | MaterialPageRoute push + 底部 sheet 混用，无统一路由表 | 中 | sheet 与 page 的选择缺乏规则，同类操作（如编辑）入口形态不一致 |
| 间距系统 | 无 4pt/8pt 网格约束，padding 数值散布（8/12/16/20/24 混用无规律） | 差 | 各页面留白节奏不统一，视觉密度跳跃 |
| 组件复用 | 无设计系统层；卡片/按钮/弹层均为页面内联样式 | 差 | 圆角（8/12/16）、边框、阴影在不同模块各自为政 |

### 1.3 配色方案

| 维度 | 现状 | 评级 | 说明 |
| --- | --- | --- | --- |
| 主题基础设施 | `ColorScheme.fromSeed`（M3）+ `AppColors` ThemeExtension（`shared/theme/app_theme.dart`），浅深两态同源 | 良 | 种子色切换 + 深色模式已可用并持久化 |
| 语义色 | income/expense/warning/accent 语义色已抽取，对比度达 WCAG 4.5:1 | 良 | 红绿收支语义静态，不随主题漂移，符合记账场景 |
| 硬编码残留 | 约 9 处（`color_picker_dialog.dart:128-160`、`report_charts.dart:55`、`calendar_page.dart:208/216` 等） | 中 | 集中在遮罩白/黑与图表配色，深色模式下个别处对比度不足 |
| 预设主题 | 仅 8 个"种子色"（`kThemePresets`），非完整主题方案 | 差 | 用户只能换主色，背景/卡片/文字/边框均不可选，无"成套风格" |

### 1.4 字体排版

| 维度 | 现状 | 评级 | 说明 |
| --- | --- | --- | --- |
| TextTheme | 未定义全局 TextTheme，页面直接消费 M3 默认值或零散 `textTheme` 引用（约 26 文件） | 中 | 层级靠 M3 默认撑着，无品牌化字阶 |
| 字号硬编码 | 6 处（`amount_keyboard`、`calendar_page`、`report_charts` 等） | 中 | 金额大数字等关键场景游离于体系外 |
| 字体资源 | pubspec 无 fonts 段，无自定义字体 | 中 | 数字无等宽处理，账单金额列对不齐 |
| 字重/行高 | 无规范 | 差 | 标题与正文层级仅靠默认 size 区分 |

### 1.5 视觉风格一致性

- **图标**：已有 IconPack（线性/实心/圆角/直角）切换机制，是项目内最成熟的一致性实践，可作为主题系统的接入样板。
- **图表**：fl_chart 配色部分硬编码，与主题色脱节。
- **反馈**：SnackBar 已统一 floating；但加载态、空态、按压态无统一规范。
- **背景能力**：全项目无任何背景图/皮肤能力（无 AssetImage/DecorationImage），为净新增功能。

### 1.6 结论

主题"骨架"（M3 ColorScheme + ThemeExtension + Riverpod 持久化）质量良好，**不推翻、做扩展**；缺口在：①无完整设计 Token 层（间距/圆角/字阶/阴影）；②无成套预制主题；③无通用组件库；④无背景图与智能遮罩能力。本次重构以"Token 化 + 组件库 + 8 套主题 + 背景系统"四件事补齐。

## 2. 设计原则

1. **Token 先行**：一切颜色、字号、间距、圆角必须来自 Design Token，禁止裸值。
2. **语义优先**：颜色按用途命名（income/expense/warning），不按色相命名；收支红绿语义全主题静态锁定，不随主题漂移（中国记账习惯：收入绿/支出红）。
3. **对比度底线**：正文文字 ≥ WCAG AA 4.5:1，大号文字与图标 ≥ 3:1；每套预制主题出厂前必须通过对比度校验。
4. **一致性即组件化**：同种交互（弹层、按钮、卡片）全应用只有一个实现。
5. **反馈可见**：所有可点元素有点击态，所有异步操作有加载态，所有结果有成功/失败提示。
6. **内容可读性高于装饰**：背景图是装饰层，任何情况下不得牺牲账单数据的可读性（智能遮罩为此服务）。

## 3. 设计规范

### 3.1 色彩体系（Design Tokens）

每套主题必须完整定义以下 Token（分为四组）：

**品牌与交互**
| Token | 用途 |
| --- | --- |
| `primary` | 主色：主按钮、选中态、关键强调 |
| `onPrimary` | 主色之上的文字/图标色 |
| `primaryContainer` | 主色浅底：选中卡片底、标签底 |
| `secondary` | 辅助色：次强调、图表第二序列 |

**表面层级**
| Token | 用途 |
| --- | --- |
| `background` | 页面底色 |
| `surface` | 卡片/弹层底色 |
| `surfaceVariant` | 次级区块底（分组头、输入框底） |
| `scrim` | 遮罩基色（弹层背板、背景图遮罩） |

**文字**
| Token | 用途 |
| --- | --- |
| `textPrimary` | 标题、关键数据 |
| `textSecondary` | 辅助说明、次级信息 |
| `textDisabled` | 禁用态文字 |

**线条与语义**
| Token | 用途 |
| --- | --- |
| `border` | 卡片/输入框描边 |
| `divider` | 列表分隔线 |
| `income` / `expense` / `warning` | 收入绿 / 支出红 / 预警橙（全主题静态锁定值，见 3.5） |

### 3.2 字体系统（TextTheme）

新增全局 TextTheme，字号梯度（sp）：

| 样式 | 字号 | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- |
| displayAmount | 34 | w700 | 1.2 | 账单页总金额等大数字 |
| headline | 22 | w600 | 1.3 | 页面主标题 |
| title | 17 | w600 | 1.35 | 卡片标题、列表主文案 |
| body | 15 | w400 | 1.5 | 正文 |
| bodySmall | 13 | w400 | 1.45 | 辅助说明 |
| caption | 12 | w400 | 1.4 | 时间戳、标签 |
| amount | 17 | w600 | 1.3 | 列表金额（**等宽数字** `fontFeatures: tabular-nums`） |

规则：金额一律走 `amount`/`displayAmount` 并开启等宽数字特性；禁止页面内裸写 `fontSize`。

### 3.3 间距 / 圆角 / 阴影

| Token | 值 | 用途 |
| --- | --- | --- |
| space.xs / sm / md / lg / xl | 4 / 8 / 16 / 24 / 32 | 全部内边距与间隙，4pt 网格 |
| radius.sm / md / lg / pill | 8 / 12 / 20 / 999 | 输入框 sm、卡片 md、弹层 lg、标签 pill |
| elevation.card | y=2, blur=8, 8% 黑 | 卡片唯一阴影规格（深色主题用边框替代阴影） |
| elevation.sheet | y=-4, blur=16, 12% 黑 | 底部弹层 |

### 3.4 组件规范（统一视觉语言）

| 组件 | 规范要点 | 交互反馈 |
| --- | --- | --- |
| AppButton（primary/secondary/text/danger） | 高 48，圆角 md，主按钮 `primary`+`onPrimary` | 按压 96% 缩放 + 12% 加深遮罩，150ms；加载态内置 spinner 禁重复点击 |
| AppCard | 圆角 md，1px `border` 或 elevation.card（二选一，浅色用阴影、深色用描边） | 可点卡片按压水波纹 + 背景 4% 变化 |
| AppTextField | 填充 `surfaceVariant`，聚焦描边 `primary` 2px | 错误态描边 `expense` + 下方 12sp 错误文案 |
| AppBottomSheet | 顶部圆角 lg，拖拽柄 32×4，背板 `scrim` 54% | 下滑关闭，背景可点关闭 |
| AppDialog | 圆角 lg，标题 title + 内容 body + 按钮区右对齐 | 危险操作按钮用 danger 样式 |
| AppSnackBar | floating，成功 `income` 图标 / 失败 `expense` 图标 | 时长 2.5s，可滑动关闭 |
| AppEmptyState | 插画位 + title + bodySmall + 可选主按钮 | — |
| 图表 | 序列色从 `primary`/`secondary`/语义色派生，禁止裸 hex | 点击高亮 + tooltip 卡片化 |

动效统一：标准 200ms / 强调 300ms，曲线 `easeOutCubic`；主题切换过场 250ms 色彩插值。

### 3.5 收支语义色（全主题锁定）

| 语义 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| income 收入 | `#2E7D32` | `#81C784` |
| expense 支出 | `#C62828` | `#E57373` |
| warning 预警 | `#C2410C` | `#FFB74D` |

## 5. 自定义背景与智能遮罩设计规范

### 5.1 功能定义

- 用户可从相册选择一张图片作为**全局应用背景**（作用于五 Tab 主页面及二级页页面底层）。
- 背景为装饰层，位于：背景图 → 智能遮罩层 → 内容层 的三层结构最底。
- 支持开关、更换、恢复默认（纯色 `background`）；图片本地存储，不同步、不备份。

### 5.2 智能遮罩机制

**目标**：任意明度的背景图下，前景文字与卡片保持 WCAG AA 可读性与清晰视觉层次。

**亮度评估**：对背景图缩略采样（32×32），按 Rec.709 计算加权平均相对亮度 `L ∈ [0,1]`：
`L = 0.2126·R + 0.7152·G + 0.0722·B`（每通道先做 sRGB 线性化）。

**遮罩策略**（遮罩色取当前主题 `background` 色，保证卡片层级不被冲淡）：

| 图片亮度 L | 判定 | 遮罩透明度 α |
| --- | --- | --- |
| L ≥ 0.75 | 极亮图 | 0.82（浅色主题）/ 0.78（深色主题） |
| 0.55 ≤ L < 0.75 | 亮图 | 0.72 / 0.68 |
| 0.35 ≤ L < 0.55 | 中调图 | 0.60 / 0.58 |
| 0.15 ≤ L < 0.35 | 暗图 | 0.55 / 0.52 |
| L < 0.15 | 极暗图 | 0.50 / 0.48 |

- α 随 L 连续插值（上表为分段锚点），避免临界跳变；映射公式与锚点值以 Spec 文档 §5 为准。
- 遮罩之上叠加 8px 高斯模糊（可关闭），弱化背景细节纹理对文字的干扰。
- **校验闭环**：计算"遮罩后有效底色 = 图·(1-α) + background·α"的平均亮度，校验 `textPrimary` 对其对比度 ≥ 4.5:1，不达标则 α 自动上浮（步进 0.05，上限 0.92）。
- 状态栏/导航栏图标明暗随遮罩后有效亮度自动切换。

### 5.3 用户可调项

- 遮罩模式：**智能（默认）/ 手动**（滑杆 0–92%，实时预览）。
- 背景模糊：开 / 关。
- 应用范围：全局（默认）。

### 5.4 视觉层次规则

1. 卡片（`surface`）始终不透明，保证数据区绝对可读；
2. 页面底色让位给背景图，卡片投影在深色主题下改描边；
3. AppBar 透明化 + 遮罩一体化，滚动时内容从卡片上滑过，背景不动。

## 6. 交付与验收要点（设计侧）

1. 8 套主题在五个主 Tab 的观感截图（每套 ≥ 5 张），文字对比度校验全部通过。
2. 背景图测试集：极亮（天空）/ 亮（浅纹理）/ 中调（人像）/ 暗（夜景）/ 极暗（纯黑调）各 1 张，遮罩自动适配后账单列表可读。
3. 组件库样板间（Widgetbook 或独立 Gallery 页）覆盖 §3.4 全部组件 × 8 主题。
4. 全项目静态检查：除 Token/主题定义文件外，无裸 `Color(0x…)`、`fontSize:` 残留。
