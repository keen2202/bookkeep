## 1. 代码重构建议（Refactoring）

### BK-FX-001 统一账本刷新总线（对应 F-1、F-12、L-7）
- **现状**：记账保存后仅 invalidate 预算/账户两个 provider（`quick_entry_sheet.dart:94-95`），报表 `dailyTotalsProvider`、日历 `calendarDailyTotalsProvider` 等 FutureProvider.family 缓存无失效路径；备份恢复后同样大面积陈旧。
- **方案**：引入 `ledgerVersionProvider`（StateProvider<int>）作为全局账本版本号；所有报表/日历/账户/预算 provider 统一 `ref.watch(ledgerVersionProvider)`；任何写操作（记账、转账、CSV 导入、备份恢复、同步合并落库）后 `+1`。新增写入路径只需调用一个方法，避免 invalidate 清单随功能增长而漏项。
- **工作量**：约 0.5 天；风险低，纯客户端状态管理改动。

### BK-FX-002 Repository 依赖注入收口（对应 B-3、F-2）
- **现状**：`RecurringService(db)` 内部自建 `TransactionRepository(db)`，bookId 回退占位常量 `kDefaultBookId`，周期流水生成即丢失（已复核确认）；同类"服务自建 Repository"模式是系统性隐患。
- **方案**：禁止 Service 层 `new Repository()`，统一改为构造注入或 Riverpod Provider 读取；`TransactionRepository` 的 bookId 改为必传参数（删除 `kDefaultBookId` 回退，编译期消灭该类错误）。全局 grep `Repository(db)`/`Repository(this.db)` 排查同类问题。
- **工作量**：约 1 天（含全库排查）。

### BK-FX-003 服务端事务客户端封装（对应 B-4，阻塞）
- **现状**：`books.routes.ts:56-70,150-163` 用 `pool.query('BEGIN')` 跑事务——pg Pool 每次 query 独立借还连接，BEGIN/INSERT/COMMIT 落在不同客户端，事务完全失效，集成测试因同一 bug 反而"测过"错误实现（已复核确认）。
- **方案**：`DbPool` 接口增加 `connect()`；新增 `withTransaction(pool, async (client) => {...})` 帮助函数（持同一连接 BEGIN/COMMIT/ROLLBACK + finally release）；`POST /books`、`accept-invite` 两处路由全部改用该函数。**并强制后续所有多写路径只能经此函数**（写进 CONTRIBUTING / 代码评审清单）。
- **工作量**：约 0.5 天。

### BK-FX-004 死代码与重复实现清理（对应体积 P2、低危项）
- `account_repository.dart:119-193` 的 `createTransfer` 与 `transaction_repository.dart:99-172` 完全重复，删其一（保留 transaction 侧，account 侧改委托调用）。
- 未接线代码归档或接线：`sms_parser.dart`（纯函数无平台通道）、`currency_repository.installSeeds`（无调用方）、`budget_repository.shouldNotify/markAlertNotified`（由 BK-FX-011 接线）。
- `quick_entry_controller.dart:127-160` save() 补 try/finally 复位 `saving` 并暴露错误态（当前异常后保存永久静默失败）。

### BK-FX-005 UI 组件结构重构（对应 U-1、U-9）
- **嵌套 Scaffold 根治**：主 shell（`app.dart:67-111`）统一管理 AppBar 与全局 FAB，页面级组件（CategoriesPage/BudgetsPage 等）剥离内层 Scaffold/AppBar/FAB，标题与动作通过 shell 配置注入。
- **Tab 状态保持**：`body: switch(_tab)` 改 `IndexedStack`，保留各 Tab 滚动位置与报表筛选状态（`_range`/`_hideAmounts`）。
- 列表全量构建改 `ListView.builder/separated`（accounts/categories/budgets/recurring/member_manager 五处）。

## 2. 安全性增强措施（Security）

### BK-FX-006 启用 SQLCipher 数据库加密（对应 B-2，阻塞 + 合规）
- **现状**：`AppDatabase.openEncrypted` 与 `SecureStorageKeyStore` 已实现但零调用；`main.dart:33` 一律明文建库。与 Spec §1.3 / BK-P0-006 宣称的加密存储不符；同时 libsqlcipher.so（每 ABI 约 5MB）被打包却未使用。
- **方案**：
  1. 启动流程改为：KeyStore 读密钥 → 不存在则生成（32 字节随机）并存入 flutter_secure_storage → `openEncrypted(path, key)`。
  2. 存量明文库迁移：检测库是否加密（读前 16 字节头，`SQLite format 3` 明文头判断）→ 明文则 `sqlcipher_export` 一次性迁移 → 校验行数后切换。
  3. `PRAGMA key` 改参数化/转义（`database.dart:43` 字符串插值低风险但应顺手修复）。
  4. 失败兜底：密钥丢失/损坏时给用户提供"重置本地库"选项（明确提示数据丢失），而非崩溃。
- **验证**：BK-T-009 安全清单补"adb pull 出库文件 hexdump 前 16 字节非 SQLite 明文头"。

### BK-FX-007 服务端安全中间件基线（对应 L-4，高）
- **现状**：`app.ts:14-29` 零安全中间件；`/auth/login|register|refresh` 可无限爆破；scrypt N=2^17 每请求约 100ms，登录接口即 CPU DoS 放大器；Express 5 默认错误页泄露堆栈且客户端 jsonDecode HTML 抛 FormatException。
- **方案**：
  1. `helmet` 全局启用；CORS 显式白名单（仅 App 域名/开发环境 localhost）。
  2. `express-rate-limit`：auth 路由 5 次/分钟/IP；sync push 按用户配额（如 10 批次/分钟）。
  3. 统一 JSON error middleware（`{error: string}`）+ 404 handler，杜绝 HTML 错误页。
  4. 登录用户枚举侧信道修复（`auth.routes.ts:52-59`）：用户不存在时用预存 dummy hash 执行一次 scrypt verify，抹平时序差。
  5. 密码上限 ≤128 字符；refresh 清理语句包 try/catch（`tokens.ts:46-48` 失败致半完成态）。
  6. `JWT_SECRET` 缺失即拒绝启动（移除 `dev-secret` 默认值的部署可达性）。
  7. `index.ts` 增加 `unhandledRejection` 处理与 SIGTERM 优雅停机（pool drain）。

### BK-FX-008 服务端并发安全三件套（对应 L-1、L-2、L-3，高）
1. **建账竞态（L-1）**：自动建账收敛到 push 单一路径；`book_members` 加唯一约束兜底（每 book 仅一个 owner 的部分唯一索引 `UNIQUE(book_id) WHERE role='owner'`）；`GET /sync/pull` 对不存在账本返回 404（消除带副作用的 GET + 随机 UUID 刷库）。
2. **邀请 token 原子化（L-2）**：改单语句 `UPDATE invite_tokens SET used_at=now() WHERE token_hash=$1 AND used_at IS NULL AND expires_at>now() RETURNING ...`，按 RETURNING 行数判断成败；`PATCH /members` 目标角色限定 editor/viewer（禁止提升 owner，`books.routes.ts:214`）。
3. **pull 丢 op 窗口（L-3）**：BIGSERIAL 序列号在语句执行时分配、commit 时可见，并发推送存在永久丢失窗口。方案：`GET /sync/pull` 增加安全窗口 `AND created_at < now() - interval '2 seconds'`，客户端对已收 op 按 `op_id` 去重以容忍安全窗口内的重拉；长期可演进为事务内统一赋 seq。

### BK-FX-009 客户端安全细节
- 同步重放队列（F-6）：`_createTransaction` 因 account 未就绪跳过的 op 记录 `pending_replay` 表，账户 op 到达后重放，杜绝"推进游标即丢失"。
- 图表脱敏泄露（cashflow_chart.dart:52-64）：脱敏态 `minY/maxY` 改按固定刻度或脱敏后数据计算，不泄露金额量级。
- LWW 删除优先语义（`lww_resolver.dart:34-42`）：迟到的旧 delete 覆盖较新 update 属设计取舍，写入 Spec §1.3 冲突规则并补测试锁定语义。

## 3. 架构优化方案（Architecture）

### BK-FX-010 同步引擎接线与登录闭环（对应 B-1，阻塞）
- **现状**：SyncEngine（push/pull/LWW/401 刷新）完整实现但从未实例化；无登录/注册 UI；`serverBooksProvider` 不落本地 books 表，SyncMerger 实体清单缺 'book'（F-3）。
- **方案**：
  1. 设置页新增"账户与同步"分组：登录/注册表单（email + password）、同步状态指示、手动同步入口。
  2. `main()` 装配：读 flutter_secure_storage 中的 refresh_token → 构建 SyncEngine 并 `start()`；未登录降级为纯本地模式（op-log 照常入队，登录后自动追平）。
  3. 共享账本落地：pull 到服务端账本列表后 `createLocalBook` 缓存；SyncMerger `_entities` 增加 'book'。
  4. `_request` 扩展 DELETE/PATCH（`sync_api.dart:85-90`），为成员管理 UI 铺路；解析服务端 `{error}` 字段提升调试体验。

### BK-FX-011 预算提醒闭环（对应 F-5，高）
- `budget_progress_calculator.dart:6` 硬编码 80% 改读 `budgets.threshold`。
- 接线 `shouldNotify/markAlertNotified`：记账保存（BK-FX-001 刷新总线）后评估预算进度，达阈值且本周期未通知 → 触发本地通知。
- 引入 `flutter_local_notifications`（约 +1MB，值得）；通知渠道：预算超额提醒。
- 预算页补编辑/删除入口 + 同分类重复建预算唯一性拦截（F-10）。

### BK-FX-012 多币种主链路贯通（对应 F-8、F-9、L-5）
- 账户编辑页增加币种字段；转账按账户币种生成两条流水并写 `rate_snapshot`（替换 `transaction_repository.dart:116,126` 硬编码 CNY）。
- 汇率占位值 0.1 废除：未设置汇率的外币在报表/净资产处显式标注"未设置汇率"，提供手动汇率录入 UI；`NullExchangeRateSource` 保留为离线兜底但不再静默生效。
- 报表折算改读 `transactions.rate_snapshot`（`reports_repository.dart:189-195`），落实 Spec §4.5"历史流水不随汇率波动"。

### BK-FX-013 数据生命周期完善（对应 F-4、L-6、低危项）
- 备份表清单补 `currencies`、`recurring_rules`、`installment_plans`、`installment_schedules`；备份文件加 `schemaVersion`，恢复时校验兼容性。
- 分期排期月末回退（`recurring_service.dart:98-102`）：复用 `AnchorResolver._dayInMonth` 语义，消除 1月31日→3月3日 漂移。
- 周期规则表增加 `type` 字段（支持周期收入）；`recurring_engine.dart:74` 窗口 400 天按 interval 动态放大。
- `refreshSnapshots` N+1 改批量查询（`account_repository.dart:221-250`）；CSV commit 循环包事务（`capture_confirm_page.dart:73-84`）。

## 4. 性能改进策略（Performance & Size）

### BK-FX-014 APK 体积压缩：71MB → 约 25MB（对应体积审查，最高性价比）
- **解剖结论**：APK 99% 体积为三个 ABI 的原生库（x86_64 27MB + arm64-v8a 24.8MB + armeabi-v7a 21.4MB）；Dart 代码与资源仅约 1.5MB，无需激进 tree-shaking。
- **措施（按收益排序）**：
  1. 分发改 `flutter build appbundle`（Play 按设备下发单 ABI）；直发场景 `flutter build apk --split-per-abi`，主推 arm64-v8a 包（约 25MB，**-65%**）。
  2. release 的 `ndk { abiFilters }` 移除 x86_64（仅模拟器需要）。
  3. SQLCipher 取舍联动 BK-FX-006：启用加密则体积合理；若不启用，移除 hooks 的 sqlcipher source 改普通 sqlite3 库（每 ABI 省 4-6MB）。
  4. release 开 `minifyEnabled + shrinkResources`；构建加 `--obfuscate --split-debug-info=build/symbols`（崩溃符号化配套）。
  5. 依赖 audit：`sqlcipher_flutter_libs`/`sqlite3_flutter_libs` 均为 EOL 占位包，验证 hooks 链路后尝试移除其一。

### BK-FX-015 UI 性能与流畅度（对应 U-10 等）
- 列表改 builder（见 BK-FX-005）；`capture_confirm_page` CSV 大批量导入加分批渲染。
- 图表：饼图扇区只留百分比 + 外置 legend；折线 tooltip 配 `touchTooltipData` 格式化金额；柱状图开启 touch；坐标轴保留可读刻度。
- 全项目字号下限 12sp（当前最低 8sp，calendar_page.dart:198）；日历 `rowHeight` 适配 textScaler 或启用 `sixWeekMonthsEnforced` 防跳动。
- 记账键盘 SafeArea（U-3，targetSdk 36 edge-to-edge 遮挡"确定"键）；RuleEditSheet 补 `viewInsets.bottom` 键盘避让；保存防重入 busy 锁（U-4）。

### BK-FX-016 深色模式与设计系统（对应 U-2、U-5、U-8）
- 抽取共享 `buildTheme(Brightness)`，提供 `darkTheme` 并 `themeMode: system`；秒开模式第二个 MaterialApp 复用同一主题。
- 系统栏样式随主题 Brightness 联动（替换 `main.dart:27-32` 写死的 dark 图标）。
- 建 `AppColorsExtension`（ThemeExtension）：expenseColor/incomeColor/warningColor/brandColor 统一定义，替换 6 处文件的红/绿/橙硬编码与 `Colors.teal`；橙色文本加深色阶达 WCAG 4.5:1。
- 8 色分类调色板提取至 `core/constants`，图表与分类编辑共用。

### BK-FX-017 可访问性与交互反馈
- 颜色选择触控目标 32dp → 48dp（InkResponse 热区）。
- 自绘键盘/PIN 键加 `HapticFeedback` 与 `Semantics` 标签（读屏器可达）。
- 账户操作"长按"入口补 trailing more 图标（可发现性）；备份/恢复/WebDAV 四操作加 busy 态与进度指示；报表错误态补重试按钮（当前吞为永久 loading）。
