# 开发建议（Development Recommendations）

> 依据：《记账APP产品调研报告.html》中识别的 P0（6 项）与 P1（6 项）优先级结论
> 编号规则：`BK-P0-xxx`（核心必备）/ `BK-P1-xxx`（差异化）
> 每项含：代码编写建议、安全性增强措施、架构设计方案、开发策略，并关联 Spec 章节与任务编号，确保可追溯。

## 0. 技术栈基线（全局约定）

| 层 | 选型 | 说明 |
|---|---|---|
| 客户端 | Flutter 3.x / Dart 3 | 单代码库覆盖 iOS/Android，后续扩展桌面/Web |
| 本地存储 | Drift（SQLite）+ SQLCipher | 类型安全 ORM，库级加密 |
| 状态管理 | Riverpod | 可测试、编译期安全 |
| 同步后端 | Node.js 20 + Express + PostgreSQL 16 | 增量同步 API，op-log 模型 |
| 金额表示 | 整数最小货币单位（分）+ ISO 4217 币种码 | **禁止使用 float/double 存金额** |
| 传输安全 | TLS 1.3 + 证书固定（Pinning） | — |
| 测试 | flutter_test / mocktail / integration_test；后端 Jest + Supertest | 核心逻辑覆盖率门禁 ≥ 80% |

## P0 方案

### BK-P0-001 极速记账（<3 秒完成一笔）
- **代码编写建议**：记账入口组件化为 `QuickEntrySheet`，金额输入用自定义数字键盘（禁止系统键盘弹起延迟）；分类/账户默认值记忆（按最近一次同分类使用的账户回填）；使用 `const` 构造 + 局部 `setState` 最小化重建，冷启动到可记账路径 ≤ 3 次点击。
- **安全性增强**：金额输入端做范围校验（0 < amount ≤ 10^13 分）与非法字符过滤；输入不落日志；截屏防护（`FLAG_SECURE` 可选）。
- **架构设计**：`features/quick_entry/` 独立模块，依赖 `domain/usecases/create_transaction.dart`；Repository 先写本地 Drift 再入同步队列（写路径离线优先，UI 不等待网络）。
- **开发策略**：先做「支出」单类型闭环 → 扩展收入/转账；秒开模式与桌面小组件速记作为本方案的子迭代；以「启动→保存成功 ≤ 3 秒」为 DoD 性能基准（Profile 模式实测）。
- **关联**：Spec §3.1；任务 BK-T-002。

### BK-P0-002 多账户 / 资产管理
- **代码编写建议**：账户类型枚举化（现金/储蓄卡/信用卡/储值卡/电子钱包/负债）；余额不直接存储，由流水聚合 + 快照表缓存（避免漂移）；转账实现为「同一事务两条流水 + transfer_id 关联」。
- **安全性增强**：账户余额为敏感字段，隐私锁开启时列表页脱敏（`*` 显示）；删除账户需二次确认且禁止删除仍有关联流水的账户（软删除归档）。
- **架构设计**：`features/accounts/`；`AccountBalanceCalculator` 领域服务负责余额/净资产聚合；快照表 `account_snapshots` 按日刷新。
- **开发策略**：首版支持 5 类账户 + 归档；信用卡免息期/还款提醒放入 P1-004 周期模块联动，不在本方案内做深。
- **关联**：Spec §3.2；任务 BK-T-003。

### BK-P0-003 分类体系 + 自定义
- **代码编写建议**：一二级分类表（parent_id 自关联），内置 60+ 默认分类作为 seed 数据（version 化，便于升级迁移）；图标使用矢量映射表而非图片资源，减小包体。
- **安全性增强**：用户自定义分类名做长度（≤ 20 字符）与敏感词过滤；seed 数据与 user 数据隔离（`is_system` 标记），防止迁移脚本误删用户分类。
- **架构设计**：`features/categories/`；分类解析走 `CategoryResolver`（id → 名称/图标/颜色），支持软删除（历史流水保留原分类名快照字段）。
- **开发策略**：先内置不可改系统分类 + 可增删自定义分类；分类排序/收支颜色自定义作为子迭代。
- **关联**：Spec §3.3；任务 BK-T-004。

### BK-P0-004 预算（总预算 / 分类预算）
- **代码编写建议**：预算周期以「月起始日」可配置（默认 1 号）；已用额度 = 周期内流水聚合（SQL 聚合而非内存遍历）；超支判定阈值可配（默认 80% 预警 / 100% 超支）。
- **安全性增强**：预算提醒通知内容不含具体金额详情（锁屏泄露防护）；预算数据同样纳入隐私锁脱敏范围。
- **架构设计**：`features/budgets/`；`BudgetProgressCalculator` 纯函数化（输入流水集合 + 预算配置 → 进度/剩余/日均），便于单测。
- **开发策略**：首版月度总预算 + 一级分类预算；年度预算、日均动态预算、预算结转作为子迭代（结转算法需冻结窗口，避免并发记账造成抖动）。
- **关联**：Spec §3.4；任务 BK-T-005。

### BK-P0-005 基础报表（饼图 / 柱状 / 折线）
- **代码编写建议**：使用 fl_chart；报表查询层与 UI 解耦（`ReportQuery` 返回 DTO）；按日/周/月/年 + 自定义区间；分类占比用单条分组 SQL，避免 N+1。
- **安全性增强**：报表页纳入隐私锁范围；导出/分享图片时提供「隐藏金额」开关。
- **架构设计**：`features/reports/`；查询走只读 Repository（`reports_repository.dart`），命中本地物化视图 `mv_category_daily`（按日聚合表，流水变更时增量刷新）。
- **开发策略**：先三类图表 + 排行列表；现金流预测等高级图表明确推至 P2，不在本方案投入。
- **关联**：Spec §3.5；任务 BK-T-006。

### BK-P0-006 云端同步 + 隐私锁
- **代码编写建议**：同步采用 op-log（操作日志）模型：本地每次增删改生成一条 op（含 lamport 逻辑时钟 + 客户端 id），推拉分离；冲突策略 LWW（last-write-wins）+ 删除优先；隐私锁支持生物识别（local_auth）+ PIN 回退，PIN 存 PBKDF2 哈希（≥ 100k 迭代）。
- **安全性增强**：TLS 1.3 + 证书固定；JWT access(15min)/refresh(30d) 且 refresh 轮换；本地库 SQLCipher 加密，密钥由设备 Keystore/Keychain 托管；同步载荷敏感字段（备注/金额）可选 E2E 加密（二期）；所有 API 参数化 + 服务端鉴权到 book 粒度；日志全量脱敏。
- **架构设计**：`features/sync/`（client）+ `server/src/sync/`（server）；同步状态机：`idle → pushing → pulling → merging → idle`；离线队列持久化于 Drift `sync_ops` 表，断网自动恢复。
- **开发策略**：先单设备同步闭环 → 多设备并发冲突测试；隐私锁与同步解耦并行开发；服务端先行契约（OpenAPI 3.1 定义，前后端按契约 mock 并行）。
- **关联**：Spec §3.6；任务 BK-T-007（同步）、BK-T-008（隐私锁）。

## P1 方案

### BK-P1-001 多账本 + 共享账本
- **代码编写建议**：`books` 与 `book_members`（owner/editor/viewer 三角色）；所有业务表带 `book_id`，查询层强制 book 过滤（Repository 基类注入当前 book 上下文，杜绝越权读取）。
- **安全性增强**：邀请链接带时效 token（72h，一次性）；成员移除后立即失效其同步凭据；服务端每个写操作校验成员角色权限矩阵。
- **架构设计**：`features/books/`；共享账本的 op-log 按 book 分区，服务端 `sync_ops` 表以 `(book_id, seq)` 为序。
- **开发策略**：先本地多账本（免费策略对齐调研结论：多账本/共享做差异化卖点）→ 再开共享邀请；权限矩阵先用三角色，不做细粒度 ACL。
- **关联**：Spec §4.1；任务 BK-T-010。

### BK-P1-002 自动 / 智能记账
- **代码编写建议**：三通道：①CSV 导入（支付宝/微信模板解析器，策略模式每渠道一个 Parser）；②Android 通知监听 + 短信解析（正则 + 金额/商户抽取）；③AI 语音记账（语音转文本后走规则引擎抽取金额/分类/时间，预留 LLM 接口抽象层）。
- **安全性增强**：通知/短信权限按需申请并明示用途；解析结果必须经用户确认页才可入账（**禁止静默写入**）；语音音频默认不出设备，云端识别需显式授权。
- **架构设计**：`features/auto_capture/`；统一 `CaptureCandidate` 中间模型 → 确认页 → `create_transaction` 复用 P0-001 写路径。
- **开发策略**：CSV 导入先行（无权限成本、价值确定性最高）；Android 自动识别次之；iOS 走快捷指令截图方案文档化；AI 语音放最后并做开关。
- **关联**：Spec §4.2；任务 BK-T-011。

### BK-P1-003 本地 / WebDav 备份 + 导出
- **代码编写建议**：导出 CSV/Excel（Excel 用 `excel` 包或降级 CSV）；备份为「全量 Drift 快照 + 附件清单」打包 zip；WebDav 用 `webdav_client`，支持自定义端点。
- **安全性增强**：备份文件 AES-256-GCM 加密，密钥由用户备份口令经 PBKDF2 派生（口令不落盘）；WebDav 仅允许 HTTPS 端点；恢复备份前强制校验文件完整性与版本号。
- **架构设计**：`features/backup/`；`BackupService` 串行化执行（防并发写库），恢复走「新库导入 → 校验 → 原子切换」。
- **开发策略**：先 CSV 导出（低成本高口碑），再 WebDav 加密备份/恢复；本地备份文件提供「上次备份时间」提醒。
- **关联**：Spec §4.3；任务 BK-T-012。

### BK-P1-004 周期 / 分期记账
- **代码编写建议**：周期规则表（RRULE 子集扩展：**日/周/月/季/年** + 间隔 + 结束条件；季度以 `FREQ=MONTHLY;INTERVAL=3` 等价展开，避免引入非标准 FREQ）。**每种频率提供时间锚点快捷选项**：
  - 日：具体时刻（默认 09:00 入账时间，可改）
  - 周：周一 ~ 周日
  - 月：月初(1日) / 月中(15日) / 月末(最后一日) / 自定义日期
  - **季：季度初(季度首月1日) / 季度中(季度次月15日) / 季度末(季度末月最后一日) / 自定义日期**（自然季度 Q1=1~3月、Q2=4~6月、Q3=7~9月、Q4=10~12月）
  - 年：年初(1月1日) / 年中(7月1日) / 年末(12月31日) / 自定义日期
  锚点在规则表中以 `frequency + anchor_type + anchor_day` 持久化，展开引擎统一由锚点解析为具体 RRULE（锚点语义集中在一个 `AnchorResolver`，禁止在 UI 层散落计算）。本地 WorkManager/BGTaskScheduler 调度，App 启动时补跑漏执行任务（幂等：以 `rule_id + due_date` 去重）；分期关联信用卡账户额度。
- **安全性增强**：自动生成的流水带 `auto_generated` 标记，可批量追溯/撤销；任务执行失败记审计日志；季度/年度锚点跨年展开结果记审计快照，便于核对。
- **架构设计**：`features/recurring/`；`RecurringEngine` 纯函数计算「到期任务集合」，`AnchorResolver` 负责锚点→日期序列映射（输入频率+锚点+起始日，输出 RRULE/日期序列），写路径仍复用 `create_transaction`。
- **开发策略**：先固定金额周期记账（含**季度频率与全部锚点选项**，锚点解析与引擎同迭代交付，不后置）→ 分期（等额）→ 还款提醒；不做浮动金额预测。
- **关联**：Spec §4.4；任务 BK-T-013。

### BK-P1-005 多币种 + 汇率
- **代码编写建议**：币种表内置 100+ ISO 4217；每笔流水存「原币金额 + 币种 + 记账时汇率快照」三要素（汇率变化不回溯历史）；汇总展示统一折算主币种。
- **安全性增强**：汇率源 HTTPS 获取并校验响应签名/结构；获取失败回退最近缓存汇率并标注「非实时」。
- **架构设计**：`features/currency/`；`ExchangeRateService` 带本地缓存（24h TTL）；聚合换算在 `Money` 值对象内完成（整数运算，汇率用定点数）。
- **开发策略**：先手动汇率 + 每日自动更新；跨币种转账汇率差损益记录作为子迭代。
- **关联**：Spec §4.5；任务 BK-T-014。

### BK-P1-006 日历 / 现金流视图
- **代码编写建议**：日历用 `table_calendar` 自定义渲染；日聚合数据复用 P0-005 的 `mv_category_daily` 物化视图；月份切换懒加载。
- **安全性增强**：日历页纳入隐私锁脱敏；小组件（桌面日历）默认隐藏金额，点击进 App 验证后可见。
- **架构设计**：`features/calendar/`；只读查询模块，不写数据；现金流趋势 = 日净额滑动窗口聚合。
- **开发策略**：先收支日历（日格显示收支净额）→ 现金流趋势图 → 预算进度叠加。
- **关联**：Spec §4.6；任务 BK-T-015。
