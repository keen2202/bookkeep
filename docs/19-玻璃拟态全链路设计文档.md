## 1. 背景与目标

### 1.1 为什么是 v3

Glassmorphism v2 完成了「玻璃的骨架」：8 套预制主题携带 `ambient/glassFill/glassFillStrong/glassBorder` 四组 Token，卡片、弹层、导航栏换上了半透明填充 + 高光描边。但静态走查（2026-08-24，`app/lib` 全量）暴露出四个与「全链路玻璃拟态」目标的结构性差距：

| # | 差距 | 现状证据 | 影响 |
| --- | --- | --- | --- |
| G1 | **无分层模糊体系** | 卡片/弹层/导航栏只有填充 alpha 差异，除图标容器（σ=10）外无真实 `BackdropFilter` 分级 | 所有表面「透明度不同但磨砂相同」，层次感靠 alpha 单维度支撑，悬浮视窗质感不足 |
| G2 | **无光影折射细节** | `AppGlass.glassCardDecoration` 无顶部高光渐变；描边 alpha 在 0x99（60%）/0x38（22%）间漂移，未收敛到规范值 | 玻璃「平」而无「光泽」，边界语言不统一 |
| G3 | **环境光完全静止** | `AmbientGradient` 注释明确「纯静态绘制（无动画）」，页面切换/交互对背景零反馈 | 沉浸感缺失，玻璃卡片透出的环境色永远不变 |
| G4 | **组件玻璃化未闭环** | `AppButton` 主按钮实色、`AppTextField` 填充 `surfaceVariant` 不透明、下拉菜单/复选框/图表容器无玻璃规格 | 交互组件与玻璃卡片视觉语言割裂，「全组件玻璃化」未达成 |

### 1.2 目标

在**不推翻 v2 骨架**的前提下（沿用 `ThemePalette`/`AppTokens`/`ThemeTransition`/`AppBackground` 接线），完成四件事：

1. **通透层次体系**：建立 L0–L4 五层玻璃表面规格，每层差异化模糊半径与填充透明度，形成清晰深度关系；
2. **光影边界细节**：1px 半透明白色内描边收敛至规范值 + 全部玻璃表面顶部 inset 高光渐变（模拟光线折射）；
3. **动态色彩融合**：环境光渐变持续缓慢漂移，页面切换/Tab 切换触发微妙位移脉冲；全主题背景禁用纯黑/纯白；
4. **全组件玻璃化**：按钮/输入框/下拉菜单/复选框/开关/滑杆/图表容器/图标全部纳入玻璃语言，具备悬停/聚焦/按压三态过渡。

### 1.3 非目标

- 不改动数据层、同步协议、业务逻辑（纯视觉/交互层重构）；
- 不引入第三方玻璃组件库（自研 `GlassPanel`，避免依赖膨胀）;
- 不做 iOS 系统级毛玻璃桥接（`BackdropFilter` 已覆盖需求）；
- 不新增服务端接口；个性化设置全部存本地 `app_meta`。

## 2. 设计原则

| 原则 | 含义 | 落地约束 |
| --- | --- | --- |
| **光先于形** | 玻璃的质感来自「透出的光」而非「自身的色」；先设计环境光，再设计玻璃 | L0 环境层先行设计（§4），玻璃 Token 由环境光推导 |
| **深度可读** | 任何层级差异必须同时体现在 ≥2 个维度（模糊半径 + 填充 alpha + 描边亮度），不允许单维度分层 | §3 层级表每层三参数单调递增 |
| **性能是设计约束** | 每一处 `BackdropFilter` 都要有预算、测量方法与降级路径 | §7 性能预算表 + 三档画质降级 + Spec AC-06 测量方案 |
| **一致性高于个性** | 个性化只允许调「强度」，不允许调「语言」；所有表面从同一 Token 层取值；强度调整不得突破对比度下限 | §4.5 ContrastGuard 自动钳制 + Spec §8 门禁 |
| **可访问性兜底** | 玻璃再透，文字对比度不退让；动效可关 | WCAG AA 锁定测试 + `disableAnimations` 全链路尊重 |

## 3. 玻璃层级体系（通透层次）

### 3.1 五层深度模型

以「离用户越近 → 越亮、越磨砂、描边越高光」为深度语义：

```
L4 悬浮提示层   FAB / SnackBar / Toast / Tooltip        σ=36
L3 浮层        弹窗 / 底部弹层 / 下拉菜单 / 日期选择器   σ=28
L2 吸附层      底部导航栏 / 吸顶 AppBar / 快速入口悬浮条  σ=16
L1 内容面板层   数据卡片 / 图表容器 / 列表分组容器        σ=10
L0 环境层      环境光渐变 / 自定义背景图+智能遮罩         —（自身即光源）
────────────────────────────────────────────────────
内容（文字/图标/分割线）不属于玻璃层，永远实色渲染于所属层之上
```

各层填充 alpha、描边 alpha 的精确取值、深浅主题差异及画质档补偿见 **Spec §2.1 参数总表**（本文档只定语义，数值以 Spec 为唯一事实源）。设计语义：

- **L1 内容面板**是玻璃的「主声部」——占屏幕面积最大，透出环境光最多，磨砂 σ=10 足以柔化背景光斑边界但不吞掉色彩；
- **L2 吸附层**是「悬浮视窗」的边框感来源——导航栏/吸顶栏比卡片更亮更磨砂，滚动内容从其下方穿过时产生真实的「玻璃板悬浮于内容上」错觉；
- **L3 浮层**承担模态注意力——更高填充 + 更大 σ，背景内容被充分雾化，弹窗文字对比度不依赖下层；
- **L4 悬浮提示**最亮最磨砂，与 L3 拉开半档，保证 FAB 永远是视觉最高点。

### 3.2 与 v2 的兼容

v2 的 `glassFill`（α 0.65）与 `glassFillStrong`（α 0.90）语义保留，映射为：`glassFill → L1 基准`、`glassFillStrong → L3 基准`。v3 将其从「两个常量」升级为「按层级 + 明暗 + 画质档解析的函数」（Spec §2.2），存量调用点由组装器统一改读该函数，**调用方零改动**。

## 4. 环境光系统（动态色彩融合）

### 4.1 光环境构成

L0 层由三部分叠加（自底向上）：

1. **底色**：`palette.background`——主题色温的「空气」，禁止纯黑/纯白（§4.7）；
2. **光斑 Mesh**：4 个 RadialGradient 软衰减色斑（v2 为 3 个），布局锚点固定左上/右中/左下/右上，色值取 `palette.ambient`（4 色成套）；
3. **动态漂移**：每个光斑沿椭圆轨道缓慢游移（§4.2）。

### 4.2 动态漂移（Ambient Motion）

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 漂移周期 | 36s / 光斑（相位错开 90°） | 「察觉不到在动，但看久了发现光变了」 |
| 轨迹 | 椭圆轨道，长轴 = 光斑尺寸 × 6%，短轴 × 4% | 幅度克制，无眩晕感 |
| 缓动 | 正弦往复（sin/cos 驱动，无关键帧跳变） | 无限循环无接缝 |
| 页面切换脉冲 | push/pop 时全体光斑沿导航方向位移 +3%（600ms easeOutCubic 回弹归位） | 仅环境光渐变模式生效（§4.6） |
| Tab 切换脉冲 | 光斑整体 ×0.5s 呼吸一次 | 幅度低于页面切换 |
| 刷新率 | 动画帧仅重绘 L0 RepaintBoundary | 背景动画不参与内容层重建 |
| 降级 | `disableAnimations` / 省电档 / 锁定态 / 应用后台 / 背景图模式 → 静止或关闭脉冲 | 可访问性与性能兜底 |

**关于「动态漂移 × 静态模糊是否不适」的澄清**（评审意见 #3 相关）：环境光路径**不存在独立的模糊 pass**——光斑边缘的柔和感直接烘焙在 RadialGradient 的衰减曲线里（§4.4），因此漂移时没有任何「模糊半径变化」，只是软渐变整体平移，不会产生呼吸式胀缩感。图像路径的 8px 模糊作用于静态图片，σ 恒定，遮罩呼吸默认关闭（§4.6）。

### 4.3 个性化强度

外观页新增「环境光」设置组：动效开关（默认开）、光斑强度三档（含蓄 60% / 标准 85% / 浓郁 110%，缩放光斑 alpha）、页面切换位移开关（默认开）。强度调整受 §4.5 对比度联动约束——**个性化让位于可读性时自动钳制并向用户说明**。

### 4.4 标准画质档下的「伪磨砂」（评审意见 #2 回应）

标准档 L1/L2 无真实 `BackdropFilter`，通透磨砂感由三个手段合成：

1. **软化内建于渐变（核心手段）**：光斑衰减曲线按画质档分化——高保真/省电用两段急衰减 `[α0.95I, 0]`，标准档用三段缓衰减 `[α0.95I @0, α0.45I @0.55, 0 @1]`，把「模糊」预烘焙进渐变本身，光斑边缘天然无硬边；透过 α≈0.61 的 L1 填充观察时，等效于隔了一层轻磨砂。此方案漂移零额外成本（无独立模糊 pass）。
2. **填充补偿**：标准档 L1 填充 alpha 浅色 +0.06（0.55→0.61）/ 深色 +0.04（0.66→0.70），L2 浅 +0.03 / 深 +0.02，掩盖残余边缘过渡；saver 档补偿更多（Spec §2.3 表）。
3. **图像路径既有预模糊**：自定义背景图模式下全局 8px 高斯模糊已存在（v2），fill-only 天然成立。

若 BK-GLS-000 原型走查仍判定「边缘生硬」，后备手段为光斑数量 4→5（更小更密、重叠羽化），不改架构。

### 4.5 对比度联动机制（ContrastGuard，评审意见 #4 回应）

环境光强度三档会改变光斑 alpha，进而影响玻璃卡片上文字的有效对比度。规则：

- **最坏情况建模**：文字所在处的背景 = `composite(glassFill, composite(background, 最亮环境光斑中心色 × (0.95 × 强度系数 × 0.85)))`（0.85 为光斑透过玻璃的中心透过率经验系数，BK-GLS-000 实测校准）;
- **下限**：正文 textPrimary 对比度 ≥ 4.5:1；大金额数字（displayAmount，≥18sp w700）≥ 3.0:1；
- **自动钳制顺序**：浓郁→标准→含蓄 逐级回退；仍不满足则运行时提升该场景 glassFill alpha +0.05（不写盘、不改用户设置）；
- **用户感知**：外观页强度选项旁显示「已自动限制强度以保持对比度」徽标；锁定态金额脱敏逻辑不受影响（脱敏优先级最高）;
- **测试锁定**：8 预设 × 3 强度 × 浅深两态共 48 组合全部达标（单元测试），新增强度档或预设必须先过此门。

### 4.6 背景图模式专项（评审意见 #8 回应）

自定义背景图启用时：

| 项 | 行为 | 理由 |
| --- | --- | --- |
| 光斑 Mesh | 隐藏（图即光环境） | v2 既定 |
| 页面切换/Tab 脉冲 | 默认关闭（设置项仍可手动开启，作用于遮罩明度 ±2% 微呼吸） | 图像纹理下位移脉冲意义弱且易显晃动 |
| L1 填充 | 在画质档补偿基础上再 +0.06（上限 0.80） | 复杂纹理降低有效对比，加厚主声部即可 |
| 描边/高光/层级 σ | 不变 | 保持层级语言跨模式一致，避免「换背景换语言」 |
| 可读性兜底 | 智能遮罩亮度闭环沿用（`luminance.dart`）；关闭模糊时闭环自动提高遮罩 alpha（v2 既有） | 保证任意图片下 effLum 收敛 |

即：背景图模式通过「智能遮罩 + L1 加厚」维持通透感平衡，而不是改描边或模糊体系。

### 4.7 背景纯色禁令

- 全部主题 `background` 禁止 `#FFFFFF`/`#000000` 及相对亮度 ≥0.99/≤0.01 的取值；
- v3 将三套深色预设（T5/T7/T8）的 `background` 上调 3–5 个明度档（如 T5 `#0F1215 → #13171C`），让深色玻璃有可透之光；
- 单元测试锁定：8 预设 + custom 派生路径 background 相对亮度 ∈ (0.01, 0.99) 且 `ambient.length == 4`。

## 5. 光影边界细节

### 5.1 内描边（玻璃轮廓）

统一 **1px 逻辑像素半透明白描边**，基准值即需求给定的 `rgba(255,255,255,0.2)`：

- **浅色主题**：L1 0.20 / L2 0.22 / L3 0.25 / L4 0.30（严格采用需求基准）；
- **深色主题**：不做简单系数相乘，而是逐层实测设定 **0.16 / 0.18 / 0.20 / 0.24**——评审指出的风险成立：按 ×0.6 计算的 L1=0.12 合成后与填充的对比度仅 **1.44:1**，肉眼近乎不可见；0.16 实测 **1.64:1**（T5 石墨·夜、标准档合成色 #181C22 上验算，过程见 Spec §2.4），达到装饰性细线的可见下限；
- **可见性下限规则**：任一层描边与其内侧填充合成色的 WCAG 对比度 ≥ **1.5:1**（装饰性线条内部规范，区别于文字 AA），纳入单元测试；浅色主题因填充近白、白描边增量有限，轮廓定义主要由阴影 + 顶部高光 + 光斑饱和色差承担（§5.3），BK-GLS-000 做 A/B 小样确认，若不过关则启用 `borderBoost` 备选参数（浅色 L1 0.20→0.32）；
- v2 遗留的 `0x99FFFFFF`（60%）与 `0x38FFFFFF`（22%）两套漂移值全部收敛进上表。

### 5.2 顶部 inset 高光（光线折射）

CSS `inset box-shadow` 在 Flutter 无直接对应物，映射方案：**ForegroundDecoration 顶部渐变高光**——

```
LinearGradient(
  begin: topCenter, end: Alignment(0, 0.45),
  colors: [白 α_top, 白 0],
)
```

- α_top：浅色 0.25 / 深色 0.10 基准，按层 ×（L1 1.0 / L2 1.1 / L3 1.2 / L4 1.3）微调；
- 叠加顺序：填充 → 描边 → 顶部高光（高光压在描边内侧，模拟光从上沿进入玻璃的折射）。

**实现可行性论证**（评审意见 #1 回应）：

1. **性能**：ForegroundDecoration 只是在同一画布多画一次带 shader 的 drawRect，**无 saveLayer**；每面板净增成本 <0.1ms，视口面板数 ≤8 时总开销可忽略；列表行不使用 GlassPanel（fill-only 行容器，§7.1），不存在批量叠加场景；
2. **色带（banding）风险与对策**：低 alpha 渐变在 8bit 色深下可能出现台阶纹。四重防线——①渐变 stop 间隔 ≥0.15 且高光带高度固定为卡片高度的 45%（足够平缓）；②同一区域叠加的半透明渐变层数 ≤2（高光 + 至多一个图表系列渐变，互不重叠区域绘制）；③Impeller 渲染引擎对渐变自带抖动（当前 Flutter 默认后端）；④样板间内置「色带探针」展项（纯黑底放大高光条），BK-GLS-000 人工走查；若真机仍可见色带，启用降级方案 `glassHighlightStyle=solidLine`：以 1px 实线（α_top）+ 其下 1px 半强线替代渐变，视觉损失可控且实现为单点 feature flag；
3. **与复杂背景的冲突**：高光绘制于玻璃面板自身图层之内（ForegroundDecoration 位于填充之上、内容之下），与背景图/光斑无混色模式交互，不存在叠加冲突；唯一影响是其可见度依赖下层填充亮度——深色主题 α_top 0.10 即为此调低，避免暗部「泛白雾」；
4. **原型验证**：以上结论均列为 BK-GLS-000 小样验证项，实测数据回填 Spec §2.4 后才允许 W1 冻结参数。

### 5.3 悬浮阴影

保留 v2 双态阴影（浅色 y=4/blur=18/10% 黑；深色同尺寸 25% 黑），按层缩放：L2 ×1.2、L3 ×1.5、L4 ×1.8（offset/blur 同比）。浅色主题下阴影承担「玻璃边缘物理存在感」的主要职责（弥补白描边的低对比），深色主题下与描边共同构成轮廓。

## 6. 全组件玻璃化

### 6.1 交互组件

| 组件 | 玻璃规格 | 三态过渡 |
| --- | --- | --- |
| **AppButton.glass**（新增变体） | L2 填充 + σ16 磨砂 + 描边 + 顶部高光；主按钮为「品牌色玻璃」（primary α0.90 叠加白高光），次/危险按钮为中性玻璃 | hover：描边 α+0.08 + 高光 +0.05（120ms）；focus：primary 2px 外环 + α0.18 光晕（150ms）；press：0.96 缩放 + 填充加深（150ms，沿用 v2 手势） |
| **AppTextField** | 填充改玻璃：浅色白 α0.12 / 深色白 α0.06，置于玻璃卡片内自动融合 | hover：描边白 0.35（120ms）；focus：primary 2px 描边 + 外发光（180ms）；error：expense 描边 + 光晕 |
| **下拉菜单**（DropdownMenu/PopupMenu） | 弹出容器按 L3 规格渲染 | 展开 150ms fade+4px 上移；条目 hover 玻璃高亮 8% |
| **复选框/开关/滑杆** | 轨道/未选框 L1 玻璃填充 + 描边；选中态语义色实心（可读性优先） | 过渡 150ms；开关拇指带 1px 高光点 |
| **ChoiceChip/FilterChip** | 未选 L1 玻璃；选中 primaryContainer α0.70 | 选择 150ms scale 弹性 |

### 6.2 数据可视化容器

- 报表三图（饼/柱/折）、现金流趋势图、预算进度条容器统一包 `GlassPanel(tier: panel)`；
- **标准档下的玻璃感来源**（评审意见 #5 回应）：①§4.4 的软化光斑 + 填充补偿使容器呈现磨砂观感；②图表容器专属 `innerSheen`：容器底部 4% 白自下而上微渐变（模拟玻璃厚度反光，单次 drawRect 成本可忽略）；③描边 + 顶部高光 + 阴影完整保留——三者才是轮廓与质感的主承载，σ 只是锦上添花；高保真档自动获得 σ10 真实磨砂；
- 图表内部：网格线 `palette.divider` α0.5（保证刻度在任何档位清晰）；柱/折线下方 12% alpha 语义色渐变填充（「光透过图表」感主要由此承担，且不受画质档影响）；
- `chart_colors.dart` 扩展为从 `palette.ambient + semantic` 派生分类色序列（8 色），图表与所在主题光环境同源（锁定测试防漂移）。

### 6.3 图标

- 线性风格为默认 IconPack（`AppIconPack.outline`），实心仅用于选中态导航项；
- 全部图标承载于 `GlassIcon`（v2 已有），其填充/描边改读 L1 层级函数，与卡片完全同源；
- 图标本体颜色 `textPrimary`/`textSecondary`，语义图标（收入/支出）用语义色，禁止纯黑图标置于玻璃容器。

### 6.4 页面级接线

15 个 feature 模块的页面骨架（`Scaffold` 透明底 + `AppBackground`）v2 已就位，v3 需要：①卡片类容器换 `GlassPanel`（API 兼容 `AppCard`）；②页面内散落装饰（约 ≤12 处，清单见 Spec 附录 A）收敛到层级 Token；③图表容器包玻璃。**变更影响文件全量清单见 Spec 附录 A**（评审意见 #6 回应）。

## 7. 性能策略

### 7.1 预算与测量方法（评审意见 #3 回应）

| 项 | 预算 | 手段 |
| --- | --- | --- |
| 报表 10k 条渲染 | < 500ms（v2 基线不回退） | 列表行级元素 fill-only（无 BackdropFilter）；L1 真实磨砂仅用于视口内整卡容器（≤6 个） |
| 背景动画帧成本 | 背景层 raster 帧均 ≤ 2ms | 动画仅重绘 L0 RepaintBoundary；后台/锁定自动暂停 |
| 长列表滚动 | 平均帧构建时间 vs v2 基线差 ≤ +5% | 列表行不走 GlassPanel；光斑动画与列表滚动分属两个 RepaintBoundary |

**测量方法**（细则与自动化见 Spec §9/AC-06）：

- **设备基线**：中端 Android（骁龙 695/765 档，如 Pixel 6a / Redmi Note 12 级别）为主测机，旗舰机为上限参照；
- **工具**：`flutter run --profile` + DevTools Performance（手动复核）；自动化用 `flutter drive` + integration_test Timeline 采集 frame build/raster p95 与丢帧率，结果落盘 `docs/report/gls-v3/perf.json`；
- **场景**：冷启动进账单页 / 报表页 10k 首帧 / 账单 200 条快速 fling ×10 / 五 Tab 连续切换 ×10（触发 breathe+pulse）/ 样板间静置 60s 统计背景动画帧成本；
- **监控**：nightly workflow 追加 perf job 先记录不设门禁，连续两版回归 >10% 则升级为 CI 门禁。

### 7.2 画质三档（用户可调，默认「标准」）

| 档位 | L1/L2 磨砂 | L3/L4 磨砂 | 环境光动效 | 目标设备 |
| --- | --- | --- | --- | --- |
| 高保真 | 真实 BackdropFilter σ10/16 | σ28/36 | 开 | 旗舰机/桌面端 |
| 标准（默认） | fill-only + §4.4 软化补偿 | 真实 σ28/36 | 开 | 主流机型 |
| 省电 | fill-only + 强补偿 | σ×0.6，仅模态弹出瞬间启用 | 强制关 | 低端机/长续航 |
